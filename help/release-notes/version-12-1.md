# バージョン 12.1

<b>Substance 3D Painter 12.1</b>では、自動リベイク処理とゆがみ補正ペインティング、UVマテリアル定義のサポート、および自動OpenPBRラップ解除用の新しいハードサーフェスモードにより、ベイクワークフローが改善されています。

リリース日： <b>2026年6月22日</b>

>[!NOTE]
>
> サポートされるmacOSの最小バージョンが13.0(Ventura)に更新されます。 詳しくは、[必要システム構成のページ](../getting-started/system-requirements.md)をご覧ください。

## 主な機能

### 傾斜ペイントによるベイク処理ワークフローの改善

![](../assets/v12/v12_banner_skew.jpg)

ベイクワークフローが刷新され、継続的な再ベーク、メッシュ上のゆがみ補正ペイント、エッジ保護、および再設計されたメッシュマップリストがサポートされるようになりました。

* <b>自動リベイク処理</b>

  メッシュマップは、ベイクパラメーターを調整しながら連続的に再ベイク処理できるため、変更のたびに手動でベイクをトリガーする必要がなくなります。 自動リベイク処理はマップごとに切り替えられ、一度に1つのマップに適用されます。 これは、スキューのペイントワークフローで特に便利ですが、一般的な烘焙設定を調整する場合にも便利です。

  ![](../assets/v12/v12_auto_rebake.png)

* <b>ゆがみ補正ペイント</b>

  ケージを<b>ディスタンスベース</b>モードにすると、ローポリメッシュに直接ゆがみ補正をペイントして、ベイク中に使用される投影方向を制御できます。 ブラシ、消しゴム、および多角形の塗りつぶしツールを使用できます。コンパクトなグレースケール値ピッカー、対称、および通常のブラシコントロールを使用できます（<b>Ctrlキーを押しながら右クリック</b>してブラシのサイズを変更、<b>X</b>してペイントした値を反転）。 ゆがみペイント操作は取り消すことができます。

  ![](../assets/v12/v12_skew_fix_rebake.gif)

* <b>エッジ保護</b>

  ゆがみ補正でペイントする場合、新しいエッジ保護オプションを使用すると、ハードエッジに投影された高ポリゴンの柔らかさが保持されます。 その結果は、<b>エッジ距離</b>および<b>エッジコントラスト</b>パラメーターによって制御されます。

  ![](../assets/v12/v12_skew_edge_distance.gif)

* <b>メッシュマップのデザインを変更しました</b>

  メッシュマップリストでは、マップをビューポートとして切り替える<b>プレビュー</b>、<b>クイックベイク</b>1つのマップとして切り替える、<b>自動リベイク</b>および<b>同期</b>のテクスチャセット間で切り替える（プロジェクトに複数のテクスチャセットがある場合に利用可能）、マップ単位のコントロールが提供されます。 各コントロールには、カーソルを合わせたときにツールチップが表示されます。

  ![](../assets/v12/v12_quick_bake.png)

* <b>[簡易ベイク]ボタン</b>

  [ビューポートのベイク]ボタンは、ベイクするマップの数（テクスチャセット x UV タイル x選択したメッシュマップ）を表示する1つの<b>ベイク</b>ボタンに置き換えられました。

  ![](../assets/v12/v12_bake_button.png)

>[!NOTE]
>
> ベイクの詳細については、[専用ドキュメントページ](../baking/baking.md)を参照してください。

### OpenPBR のサポート

![](../assets/v12/v12_banner_openpbr.jpg)

シェーディングモデルがPainterでサポートされるようになり、デフォルトワークフローとして使用されるようになりました。これにより、標準化されたマテリアル定義をアプリケーション間で伝送できます。

* <b>新しいOpenPBR シェーダーと既定のワークフロー</b>

  シェーダー 1.1仕様を実装するOpenPBRがデフォルトで使用可能になり、使用されます。 テンプレートなしで作成された新しいプロジェクトではOpenPBR シェーダーが使用され、新しいプロジェクトウィンドウの最初のエントリには、<b>ASM</b>ではなく<b>OpenPBR</b>というラベルが付けられます。 OpenPBR用の新しいプロジェクトテンプレートが含まれ、サンプルプロジェクトが更新されて使用されます。

  ![](../assets/v12/v12_openpbr_shader_icon.jpg)

* <b>インポート時にプロジェクトテンプレートからシェーダーが選択されました</b>

  USDまたはGLTFファイルを読み込むときに、シェーダーがファイルの内容から推測されるのではなく、プロジェクトテンプレートから設定されるようになりました。 マテリアルとテンプレートで不一致ワークフローが使用されている場合は、ログにメッセージが記録されます。

  ![](../assets/v12/v12_openpbr_template.png)

* <b>エクスポートに関するOpenPBR名前付け規則</b>

  <b>書き出しテクスチャ</b>ウィンドウに、命名規則を選択するための新しいドロップダウンが追加されました。 プロジェクト内の少なくとも1つのOpenPBRが使用されると、既定のシェーダーになり、選択したスキームが各テクスチャセットのマップの一覧に反映されます。

  ![](../assets/v12/v12_openpbr_export.png)

* <b>USDとMDLのサポート</b>

  マテリアルは、USDフォーマットでサポートされています。 新しいMDLも追加され、IrayのOpenPBRマテリアルをレンダリングして、より正確なマテリアル表現を提供できるようになりました。

>[!NOTE]
>
> カスタムシェーダを更新する必要がある場合があります。 シェーダー APIがサポートOpenPBRに変更されました。詳細については、アプリケーションのヘルプメニューにあるchangelogを参照してください。

### 新しいハードサーフェスの自動ラップ解除

![](../assets/v12/v12_banner_uvs.jpg)

ハードサーフェスアセットに合わせてカスタマイズされた新しい自動ラップ解除モードが追加されました。

* <b>ハードサーフェスラップ解除モード</b>

  自動ラップ解除の設定で、<b>ハードサーフェス</b>オプションを使用できます。 これによりUVのゆがみが最小限に抑えられ、UVレイアウトが直交投影で作成されるため、機械やハードサーフェスのメッシュにより適しています。

  ![](../assets/v12/v12_unwrap_mode.jpg)

>[!NOTE]
>
> 自動ラップ解除の詳細については、[専用ドキュメントページ](../features/automatic-uv-unwrapping.md)を参照してください。

### その他

![](../assets/v12/v12_banner_misc.jpg)

このバージョンでは、追加機能と機能強化が追加されています。

* <b>複数のチャンネルを一度に追加または削除</b>

  OpenPBRの導入後、<b>テクスチャセット設定</b>からアクセスできる新しいウィンドウでは、複数のチャンネルを一度に選択できます。これは、OpenPBRワークフローで使用する大きなチャンネル一覧を設定する場合に便利です。

  * 新しいウィンドウには、テクスチャセット設定の[<b>チャンネルの追加と削除</b>]ボタンからアクセスできます。

    ![](../assets/v12/v12_channel_add_remove_button.png)

  * ウィンドウには、Painterで使用できるすべてのチャンネルの概要が表示されます。

    ![](../assets/v12/v12_channel_window_small.jpg)

  * <b>すべてのテクスチャセットに適用</b>ボタンを使用すると、すべてのテクスチャセットのチャンネル構成を一度に編集できます。

    ![](../assets/v12/v12_channel_apply_all.png)

* <b>複数のテクスチャセット間ですべてのインスタンスを統合する</b>

  新しい<b>すべてのインスタンスを統合</b>オプションは、インスタンス化されたレイヤーおよびグループで使用できます。 インスタンスが表示されるすべてのテクスチャセットにわたって統合された結果が生成され、インスタンスツリー全体に表示されます。この結果は、1回の取り消し手順として記録されます。

  ![](../assets/v12/v12_flatten_instances.png)

* <b>元に戻す操作の統合履歴</b>

  ベイクモードとペイントモードで同じ取り消し履歴が共有されるようになりました。 ベイクモードとペイントモードの切り替えは、取り消し可能な手順として記録されるため、操作が発生したモードでのみ操作を取り消すことができます。
