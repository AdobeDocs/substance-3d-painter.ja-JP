# メッシュとUVの設定

Painter用のメッシュの準備に数分かかると、テクスチャリングプロセスをより速く簡単にすることができます。

+++多数のモデル
Painterが処理できるポリカウントの具体的なベンチマークはありません。これは、大部分がマシンの仕様、テクスチャセットの割り当て、およびレイヤースタックプロパティに依存するからです。しかし、1,000万未満のポリカウントは、レイヤースタックの最適化を考慮に入れて処理する必要があります。

+++

+++低い多数モデル
ポリが低すぎるほどのものがあります。 これは、テクスチャエンジンがポリゴンを使用して、ブラシストロークを計算するためにメッシュのどの部分をレンダリングする必要があるかを知っているためです。 Polycountの値が非常に小さいメッシュは、小さなブラシストロークでも完全に再レンダリングでき、GPUが不必要にオーバーワークする可能性があります。

たとえば、単一の四角いプレーンをテクスチャリングする場合、情報がより多くの頂点に分散されるので、特に多数のストロークを使って手でペイントする場合は、メッシュを再分割することをお勧めします。

+++

+++複数のテクスチャセットにまたがるテクスチャの分割
より複雑なマテリアルを割り当てた大きなメッシュを複数のテクスチャセットに分割するのが最適です。 テクスチャセットを使用すると、解像度やシェーダプロパティなど、テクスチャセットごとに異なる設定を割り当てることができます。 たとえば、メッシュの一部だけが半透明度またはSSSを使用する場合は、別のテクスチャセットと別のシェーダインスタンスをその部分に割り当てるのが最適です。 これにより、これらの複雑なプロパティを使用しない場所で計算する必要がなくなります。

+++

+++UV アイランドを近づけます。
3D空間で隣り合うUV アイランドは、できるだけ近くに配置してください。 これは、UDIMレイアウトとクラシックUVスペースレイアウトの両方に適用されます。 ペイントストロークまたはテクスチャリングを共有している場合は、UV空間の同じ領域に重ねられたほうが、反対側の端にある場合よりも計算が簡単です。

テクスチャエンジンは、テクスチャを小さいチャンクに分割することによって動作し、計算を高速化します。 つまり、ストロークごとにテクスチャ全体が更新されるのではなく、各ストロークによって、変更する必要のあるチャンクのみが更新されます。 隣り合うUV アイランドを近づけることにより、1回のストロークで影響を受けるチャンクの数を最小限に抑えることができます。

+++

+++オブジェクトが多くなりすぎないようにする
8000未満のサブオブジェクトを持つメッシュを読み込むときは、パフォーマンスは快適なままにする必要があります。 この制限を超えると、ビューポートとペイントのパフォーマンスに影響を与える可能性があります。 この制限に達した場合は、レンダリングのオーバーヘッドを軽減するためにオブジェクトを結合することをお勧めします。

+++
