# メッシュとUVの設定

Painter用のメッシュの準備に数分かかる場合、テクスチャリングプロセスをより速く、簡単に行うことができます。

+++多数のモデル
Painterが処理できるポリカウントの具体的なベンチマークはありません。これは、主にマシンの仕様、テクスチャセットの割り当て、およびレイヤースタックの特性に依存するからです。しかし、レイヤースタックの最適化を考慮に入れた場合、1,000万未満のポリカウントは問題なく処理されるはずです。

+++

+++低い多数モデル
ポリが低すぎるほどのものがあります。 これは、エンジンがポリゴンを使用して、メッシュのどの部分をレンダリングしてブラシストロークを計算するかを判断するためです。 Polycountが非常に低いメッシュは、小さなブラシストロークを使用しても完全に再レンダリングされ、GPUが不必要にオーバーワークする可能性があります。

たとえば、1つの四角形の平面をテクスチャリングする場合、特に大量のストロークを使って手でペイントする場合は、メッシュがより多くの頂点に分散されるので、情報を細分割することをお勧めします。

+++

+++複数のテクスチャセット間での分割テクスチャ
より複雑なマテリアルの割り当てを行う大きなメッシュを複数のテクスチャセットに分割することをお勧めします。 テクスチャセットでは、解像度やシェーダーのプロパティなど、テクスチャセットごとに異なる設定を割り当てることができます。 例えば、メッシュの一部だけがtranslucencyまたはSSSを使用する場合は、その部品に別のテクスチャセットと別のシェーダーインスタンスを割り当てるのが最適です。 これにより、これらの複雑なプロパティを使用しない場所で計算する必要がなくなります。

+++

+++UV アイランドを近づけます。
3D空間で隣り合うUV アイランドは、できるだけ近くに配置してください。 これは、UDIMレイアウトとクラシックUVスペースレイアウトの両方に適用されます。 ペイントストロークまたはテクスチャリングを共有している場合は、反対の端にある場合よりも、UVスペースの同じ領域に集めたときに計算する方が簡単です。

エンジンは、テクスチャを小さいチャンクに分割することによって機能し、計算を高速化します。 つまり、ストロークごとにテクスチャ全体が更新されるのではなく、各ストロークによって、変更が必要なチャンクのみが更新されます。 隣り合うUV アイランドを近づけることにより、1回のストロークで影響を受けるチャンクの数を最小限に抑えることができます。

+++

+++オブジェクトが多くなりすぎないようにする
サブオブジェクトが8000個未満のメッシュを読み込む場合は、パフォーマンスは引き続き向上します。 この制限を超えると、ビューポートとペイントのパフォーマンスに影響を与える可能性があります。 この制限に達した場合は、レンダリングのオーバーヘッドを軽減するためにオブジェクトを結合することをお勧めします。

+++
